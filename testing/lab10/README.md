## Тестовое окружение

Тесты **не трогают рабочую PostgreSQL-базу**: `conftest.py` подменяет
`DATABASE_URL` на временную SQLite-БД `test_tickets.db` (создаётся и удаляется
автоматически). Docker-приложение может быть остановлено — тесты поднимают
приложение в памяти через `TestClient`.

## Запуск одной командой

```bash
pip install pytest httpx fastapi "sqlalchemy>=2.0" "pydantic>=2.6" \
    "python-jose[cryptography]" "passlib[bcrypt]" "bcrypt==4.0.1" python-multipart jinja2

python -m pytest testing/lab10 -v
```

Ожидаемый результат: `23 passed`. Полный вывод последнего прогона — в `test_run.txt`.

## Как тест обнаруживает ошибку (пример)

`test_regression.py::test_search_empty_filters_ok` (регрессия BUG-01): запрос
`GET /?q=тест&status=&category_id=&priority=` — ровно то, что отправляет
браузерная форма. Утверждение `assert r.status_code == 200` **падает** на коде
до исправления, потому что сервер отвечал 422 «Ошибка валидации данных».
Аналогично `test_openapi_token_url` падает, если `tokenUrl` снова станет неверным
(BUG-03), а `test_search_by_category_name` — если из поиска убрать категорию (BUG-02).
