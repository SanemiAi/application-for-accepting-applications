# Сценарий финального видео (ЛР №10, до 5 минут)

**Как записать на Windows:** Xbox Game Bar (Win+G → кнопка записи, Win+Alt+R) или
OBS Studio. Формат MP4. Записывайте весь экран с голосом.

**Перед записью подготовьте:**
1. `docker compose up -d` — приложение работает (http://localhost:8000).
2. Откройте в браузере две вкладки: http://localhost:8000 и http://localhost:8000/docs.
3. Откройте PowerShell в папке проекта (для запуска тестов).
4. Войдите заранее под `admin` (пароль — `ADMIN_PASSWORD` из вашего `.env`;
   в репозитории пароли не публикуются) — пароль в кадр не попадает,
   если войти до начала записи.
5. Закройте лишние окна и уведомления.

## План по таймингу

### 0:00–0:20 — Представление
> «Здравствуйте. Меня зовут (ФИО), группа (номер). Представляю проект
> "Система приёма и подачи заявок" — веб-приложение с REST API на FastAPI
> и PostgreSQL, с ролями Заявитель, Оператор, Исполнитель и Администратор».

### 0:20–1:00 — Запуск и главный экран
- Покажите вкладку с приложением (список заявок, 12 демо-заявок).
> «Приложение запускается одной командой docker compose up по README.
> Это главный экран — список заявок с поиском и фильтрами по статусу,
> категории и приоритету».
- Быстро покажите фильтр по статусу «Новая» и поиск «Снабжение».

### 1:00–2:30 — Ключевой сценарий
1. Нажмите «+ Новая заявка», заполните (тема «Не работает проектор», описание,
   категория, приоритет «Высокий») → «Подать заявку».
2. Найдите её поиском по слову «проектор».
3. Откройте карточку → назначьте исполнителя (Игорь Мастеров).
4. Выйдите, войдите под `igor` (пароль — `SEED_DEMO_PASSWORD` из `.env`) →
   откройте заявку → «Взять в работу» → «Отметить выполненной» с комментарием.
5. Войдите обратно под admin → карточка показывает статус «Выполнена».
> «Заявка прошла полный цикл: создание, назначение, выполнение.
> Данные сохраняются в PostgreSQL и видны всем участникам по их правам».

### 2:30–3:15 — REST API
- Вкладка /docs: «Authorize» → логин `admin`, пароль из вашего `.env`.
- Выполните GET /api/requests → покажите HTTP 200 и JSON.
- Выполните GET /api/requests/З-999999 → покажите HTTP 404 и формат ошибки.
> «REST API задокументирован в Swagger: успешный запрос — 200,
> несуществующий объект — 404 с единым форматом ошибки».

### 3:15–4:30 — Автотесты
- В PowerShell: `python -m pytest testing/lab10 -v` (идёт ~3 секунды).
- Покажите итог: `23 passed`.
> «23 автоматических теста на отдельной тестовой базе: бизнес-логика,
> API, валидация и регрессия на три исправленных дефекта. Например,
> этот тест (покажите test_search_empty_filters_ok) проверяет исправленный
> баг: раньше поиск с пустым фильтром категории возвращал ошибку 422».
- Можно также показать `python tests/e2e_check.py` → 45 passed.

### 4:30–5:00 — Итог
> «Готовы все функции по ТЗ: заявки полного цикла, роли, поиск, фильтры,
> комментарии, REST API, деплой в Docker. Ручное тестирование — 28 кейсов,
> все пройдены; найдено и исправлено 3 дефекта. Известных ограничений:
> не проводилось нагрузочное тестирование. Спасибо за внимание».

## Проверка перед отправкой

- [ ] Длительность ≤ 5 минут
- [ ] Видно работающее приложение, а не слайды
- [ ] Не видны пароли и токены (войти до записи; в Swagger curl-строка
      содержит токен — не задерживайте кадр на ней или скройте)
- [ ] Файл MP4 открывается; если ссылка — проверена в окне инкогнито
