# Git-workflow проекта (лабораторная №2)

- `main` — стабильная ветка: сюда попадают только проверенные изменения.
- `develop` — рабочая ветка: новые функции и документы сначала коммитятся сюда.
- Слияние: после проверки (запуск приложения + `python tests/e2e_check.py`)
  ветка `develop` сливается в `main` (`git merge develop`).
- Сообщения коммитов — в формате префиксов: `docs:`, `feat:`, `chore:`, `test:`, `fix:`.
- Секреты (пароли, токены) в репозиторий не коммитятся: конфигурация — через
  переменные окружения, `.env` исключён в `.gitignore`.

## Использованные команды

```bash
git init -b main                 # создать локальный репозиторий
git config user.name / user.email  # настроить разработчика
git add <файлы> && git commit    # осмысленные коммиты по этапам
git switch -c develop            # создать ветку разработки
git switch main && git merge develop  # слить изменения в main
git remote add origin <url> && git push -u origin main develop
```

## Разбор типичного конфликта

Конфликт возникает, когда в `main` и `develop` изменены одни и те же строки файла.
Git помечает их маркерами `<<<<<<<`, `=======`, `>>>>>>>`; разрешение — вручную
оставить нужный вариант, удалить маркеры, затем `git add <файл>` и `git commit`.
Опасные команды (`git reset --hard`, `git push --force`) в этом проекте не применялись:
они безвозвратно удаляют историю/изменения.
