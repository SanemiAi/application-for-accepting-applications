# Система приёма и подачи заявок

Учебный сквозной проект (лабораторные №1–5, «Технологии разработки программного обеспечения»).

REST API + веб-интерфейс на **FastAPI + PostgreSQL** с ролевой моделью:
**Заявитель**, **Оператор**, **Исполнитель**, **Администратор**.

## Запуск

```bash
docker compose up --build
```

- Веб-интерфейс: http://localhost:8000 (вход — стартовый админ `admin` / `admin123`)
- Swagger UI (REST API): http://localhost:8000/docs
- Стартовый админ переопределяется через `ADMIN_USERNAME` / `ADMIN_PASSWORD`

Остановка: `docker compose down` (данные сохранятся); `docker compose down -v` — удалит и базу.

## Статусы и переходы

`Новая → В работе → Выполнена → Закрыта` — другие переходы запрещены, система возвращает ошибку.

## Приоритет

У заявки есть приоритет: **Низкий / Средний / Высокий** (по умолчанию — Средний).
Задаётся при создании, меняется оператором/администратором, участвует в фильтрации списка.

## Удаление заявки

Только администратор: кнопка в карточке заявки (с диалогом подтверждения) или
`DELETE /api/tickets/{number}` → HTTP 204. Комментарии удаляются каскадно.

## Веб-интерфейс

- **/** — список заявок (фильтруется по роли) с **поиском по номеру/теме и фильтрами по статусу и категории**;
- **/tickets/new** — подача заявки;
- **/tickets/{number}** — карточка заявки: полная информация, комментарии и кнопки действий по роли
  (взять в работу / отметить выполненной / закрыть — с подтверждением, назначить исполнителя);
- **/tickets/{number}/edit** — редактирование (заявитель дополняет описание, оператор/админ меняют поля).

Веб-страницы и REST API используют одни и те же правила доступа.

## REST API (префикс `/api`)

**Аутентификация (JWT)**
- `POST /api/auth/register` — регистрация (роль по умолчанию — заявитель)
- `POST /api/auth/login` — логин, выдаёт токен (в Swagger нажмите «Authorize»)

**Заявки**
- `POST /api/tickets` — создать заявку (тема, описание, категория)
- `GET /api/tickets` — список (по роли; фильтры `status`, `category_id`)
- `GET /api/tickets/{number}` — карточка заявки
- `PATCH /api/tickets/{number}` — изменения в зависимости от роли (+ поле `comment`)
- `POST /api/tickets/{number}/take` — взять в работу (исполнитель)
- `POST /api/tickets/{number}/complete` — отметить выполнение (исполнитель)
- `POST /api/tickets/{number}/close` — закрыть
- `POST /api/tickets/{number}/comments` — добавить комментарий

**Администрирование** (только admin)
- `GET/POST /api/admin/users`, `PATCH /api/admin/users/{id}` (смена роли, сброс пароля)
- `GET/POST/PATCH/DELETE /api/admin/categories`

## Поля заявки

Уникальный номер (`З-000001`), тема, описание, дата подачи, категория, статус, исполнитель, заявитель, комментарии.

## Пример сценария

1. Заявитель подаёт заявку (веб: «+ Новая заявка» или `POST /api/tickets`).
2. Оператор уточняет категорию и назначает исполнителя (карточка заявки или `PATCH /api/tickets/{number}`).
3. Исполнитель берёт заявку в работу, затем отмечает выполнение с комментарием.
4. Заявитель проверяет результат и закрывает заявку.
